# BN0 implementation and evidence audit

Date: October 31, 2026. Scope: the **protocol-1 BN0 fixture**, not the later BN1 tree or public API.

The Bun TypeScript application, real GPUI window and machine-code AOT path are demonstrated on Linux x86_64, including a release-profile native host and repeated matched development/AOT trials. Native integration [#266](https://github.com/0xPlayerOne/bun-native/pull/266) merged as `2c04f0ed991e8b5c5eecf56c9e07cbe3196e452c` after its complete required validation passed. **BN0 completion is now verified:** baseline/audit [#273](https://github.com/0xPlayerOne/bun-native/pull/273) merged as `c7bcf4e63906b97c9639c7a48ca4645d06aa98d2` after [run 41181547360](https://github.com/0xPlayerOne/bun-native/actions/runs/41181547360) passed every required job, including the rebuilt release host, actual development/AOT input and all 12 repeated baseline trials. Its supervisor-cancellation correction and scoped export cleanup are present. The owner-approved native direction has no additional human approval gate.

The acceptance sources are [#227](https://github.com/0xPlayerOne/bun-native/issues/227), [#258](https://github.com/0xPlayerOne/bun-native/issues/258), [#226](https://github.com/0xPlayerOne/bun-native/issues/226), the [master roadmap](https://github.com/0xPlayerOne/bun-native/issues/1) and [engineering-quality.md](engineering-quality.md). ### Repeated observations

These are medians of the five measured trials per mode. The summary also retains minima, maxima and nearest-rank observed p95; with five samples, p95 equals the largest observation.

| Metric                                           |   Development/JIT |  Machine-code AOT |
| ------------------------------------------------ | ----------------: | ----------------: |
| Owned window observed after fresh process launch |         128.05 ms |         129.22 ms |
| First native paint report observed               |         117.98 ms |         118.53 ms |
| Idle median combined process-tree RSS            | 156,168,192 bytes | 160,378,880 bytes |
| Sampled peak combined process-tree RSS           | 157,442,048 bytes | 161,689,600 bytes |
| OS close to observed application exit            |          26.89 ms |          26.92 ms |

Every trial starts new application and host processes, waits for initial paint, samples a two-second idle interval, injects the same click and requires matching application/native state plus exit zero. Warm-ups run the full correctness scenario but are excluded from the distributions. Measured ordering alternates between modes. OS page cache and power state are uncontrolled. These are **fresh-process startup observations**, not a controlled cold-cache result.

The driver's nominal 100 ms polling affects observation precision. The retained approximately 109 ms input-to-event/paint observations include automation and polling delay and must not be presented as native input latency. Paint callbacks are not display presentation. RSS sums can count shared pages more than once and cannot observe the true peak between samples. The data establishes a reproducible starting record, not an AOT speedup, a statistically credible regression or a hardware-GPU result. No performance threshold was invented. [NATIVE_BASELINE.md](../benchmarks/NATIVE_BASELINE.md) defines reproduction and interpretation; [engineering-quality.md](engineering-quality.md) requires matched repeated evidence before acting on a credible regression.

## #258: architecture, hygiene and validation

The v1 package graph is small: portable `@bun-native/protocol`; `@bun-native/runtime` importing only the protocol's public exports and platform APIs; the matching Rust protocol crate; one GPUI host; explicit contributor tooling and the native fixture. Solid/React adapters and shared components remain future layers in [architecture.md](architecture.md), not empty packages or duplicated native implementations in this foundation.

The AST-based [boundary check](../scripts/quality/boundaries.ts) enforces declared dependencies, export boundaries, platform isolation and inspectable imports, including type-only, dynamic, CommonJS and re-export forms. It rejects unused runtime dependencies. The strict TypeScript configuration rejects unused locals/parameters; Rust fmt, Clippy with warnings denied and protocol/native tests run in their appropriate CI lanes. [The 12 boundary tests](../tests/quality/boundaries.test.ts) deliberately exercise invalid edges, private imports, platform imports and unused dependencies. They passed during this audit, as did the boundary runner, strict 20-file type check and scoped lint.

The runtime has no external JavaScript runtime package dependency beyond the internal protocol. Development dependencies have current uses: Bun declarations, Code Foundry repository policy, Oxlint and the Oxc parser used for boundary enforcement. The root Cargo lock contains 631 target-inclusive package entries; that count is not a loaded-library or installed-size measurement. Parsed package names contain no CEF, Chromium, WebView, WebKit or Bunly dependency. GPUI's substantial native dependency graph remains part of the measured footprint and later artifact/security audits, not a reason to invent a smaller dependency count.

Manual review found and removed the unused public `MAX_TITLE_BYTES` re-export; its internal validation bound remains in use and is preserved. This changes the current source fingerprint without altering the historical manifest. The current automated checks are a scoped dependency/layering audit, not a complete whole-program unused-export or duplicate-code detector. [BN5 #259](https://github.com/0xPlayerOne/bun-native/issues/259) and [BN7 #260](https://github.com/0xPlayerOne/bun-native/issues/260) expand automation and repository-wide review. The [per-PR checklist](engineering-quality.md#7-agent-pr-checklist) already requires obsolete-path, duplicate-code, dependency, lifecycle and measured-performance review.

The original Bunly/CEF implementation, tests, distribution scripts and qualification workflows were removed under #251. The removal inventory remains in [the handoff](bun-native-handoff.md). Current source/native/AOT gates cannot inherit a passing old browser result. Required checks and draft/release protections remain active.
